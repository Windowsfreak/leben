# Leben App LLM Admin API Specification

> Administrative APIs for automated AI tools: RFC 8628 device-flow authentication, token management, content CRUD, translations, tasks, assets, and MCP protocol.

Base URL: **https://leben.8bj.de**

## Authentication

Protected administrative endpoints require an API token:
- `Authorization: Bearer <api_token>`
- `X-Admin-Token: <api_token>`

API tokens are acquired via the Device Flow (Section 1). The browser UI uses an HttpOnly `leben_session` cookie issued via `POST /api/admin/login` (Section 3). Providing a valid credential to public search endpoints (`/api/tiles`) reveals hidden and secret cards.

Errors return JSON: `{"status":"error","message":"..."}`. Missing/invalid token returns HTTP 401; rate-limited requests return HTTP 429.

---

## 1. Device-Flow Authentication (RFC 8628)

Enables passwordless token acquisition for CLI tools, scripts, and MCP servers:

1. Client calls `POST /api/auth/device` to obtain a `device_code`, `user_code` (`XXXX-XXXX`), and `verification_uri`.
2. The user opens `verification_uri` in a browser, enters the `user_code` and admin password, and approves.
3. Client polls `POST /api/auth/device/token` until the `access_token` (`lbn_...`) is issued.
4. Tokens are stored server-side as SHA-256 hashes and can be revoked at any time (Section 2).

### `POST /api/auth/device`
- **Auth**: None (rate limit: 10/min per IP)
- **Req**: Empty body (JSON `{"client_name": string}` optional)
- **Res**: `{"device_code": string, "user_code": string, "verification_uri": string, "verification_uri_complete": string, "expires_in": 600, "interval": 2}`

### `POST /api/auth/device/authorize`
- **Auth**: None (password in body authenticates approval; rate limit: 5/min per IP)
- **Req**: JSON `{"user_code": string, "password": string, "approve": boolean}`
- **Res 200**: `{"status":"success","message":"..."}`
- **Errors**: 401 (invalid password), 404 (invalid or expired user code).

### `POST /api/auth/device/token`
- **Auth**: None (polling rate limit: 60/min per IP)
- **Req**: JSON `{"grant_type": "urn:ietf:params:oauth:grant-type:device_code", "device_code": string}`
- **Pending**: HTTP 400 `{"error": "authorization_pending"}`
- **Denied**: HTTP 400 `{"error": "access_denied"}`
- **Expired**: HTTP 400 `{"error": "expired_token"}`
- **Success**: HTTP 200 `{"access_token": string, "token_type": "Bearer"}`

## 2. Token & Session Management (`/api/admin/tokens`)

### `GET /api/admin/tokens`
- **Res**: `{"status":"success","tokens":[{"id":int,"kind":"session"|"device","name":string,"user_agent":string,"ip":string,"created_at":string,"last_used_at":string|null,"expires_at":string|null,"revoked_at":string|null,"current":boolean}]}`
- `current` indicates the token used for the active request.

### `DELETE /api/admin/tokens/:id`
- **Res**: `{"status":"success","message":"Token revoked."}`
- Revokes the specified token immediately. Revoking `current` terminates the caller's session.

---

## 3. Browser Login & Health

### `POST /api/admin/login`
- **Req**: JSON `{"password": string}` (rate limit: 5/min per IP)
- **Res**: `{"status":"success","message":"Login successful.","expires_at":string}`
- Sets an `HttpOnly; Secure; SameSite=Strict` cookie (`leben_session`).

### `POST /api/admin/logout`
- **Req**: Empty
- **Res**: `{"status":"success","message":"Logged out."}`
- Revokes the caller's session/token and clears the session cookie.

### `GET /api/healthz`
- **Auth**: None
- **Res**: `{"status":"ok","db":"ok","time":string}` (HTTP 503 if database is unreachable).

## 4. Tile Management & Vector Operations

### `GET /api/admin/tiles`
- **Res**: `{"status":"success","tiles":[Tile...]}`
- Returns all tiles including hidden and secret cards.

### `POST /api/admin/tiles` or `PUT /api/admin/tiles`
- **Req**: JSON object:
  - `id` (int, optional; `> 0` updates existing, `0` or omitted creates new)
  - `name` (str, required)
  - `language` (str, e.g. "de", "en")
  - `title` (str, required)
  - `summary` (str)
  - `html_teaser` (str)
  - `content_file` (str)
  - `tags` (comma-delimited string, e.g. `"tech, code"`)
  - `type` ("doc"|"link")
  - `link` (str)
  - `secret` (str)
  - `accent_color` (hex)
  - `background` (str)
  - `visible` (bool)
  - `sort_order` (int)
- **Res**: `{"status":"success","message":"Tile saved successfully.","tile":Tile}` (Ollama vector embeddings regenerated automatically).

### `DELETE /api/admin/tile/:id` (or `/api/admin/tiles/:id`)
- **Res**: `{"status":"success","message":"Tile deleted."}`

### `POST /api/admin/tile/:id/toggle-visibility`
- **Res**: `{"status":"success","message":"Tile visibility toggled."}`

### `POST /api/admin/tile/:id/clone`
- **Res**: `{"status":"success","message":"Tile cloned successfully.","clone_name":string}`

### `POST /api/admin/tile/:id/translate`
- **Req**: JSON `{"name": string, "target_lang": string}` (or query param `target_lang`: "de"|"en"|"all", default "all")
- **Res**: `{"status":"success","message":"Translation task started...","task":Task}`
- Triggers asynchronous background translation (DeepL first, LLM fallback). Returns HTTP 409 if a task is already running for this card.

### `POST /api/admin/tiles/refresh-vectors`
- **Res**: `{"status":"success","message":"Vectors refreshed successfully for N tiles."}`

### `GET /api/admin/translation-status?name=`
- **Req**: Optional `name` query parameter
- **Res**: Translation matrix reporting source language, effective file modification times, and per-language status ("source"|"up_to_date"|"stale"|"missing").

## 5. Background Task Management (`/api/admin/tasks`)

Task schema:
```json
{
  "id": "uuid",
  "tile_name": "string",
  "target_lang": "string",
  "status": "pending|running|completed|failed|cancelled",
  "progress": "string",
  "error": "string",
  "started_at": "RFC3339",
  "completed_at": "RFC3339|null",
  "result": "any"
}
```
*Note: Task state is held in memory and resets upon server restart.*

### `GET /api/admin/tasks`
- **Res**: `{"status":"success","tasks":[Task...]}`

### `GET /api/admin/tasks/:id`
- **Res**: `{"status":"success","task":Task}` (HTTP 404 if not found).

### `POST /api/admin/tasks/:id/cancel`
- **Res**: `{"status":"success","message":"Task cancelled successfully."}`

## 6. Content & Configuration APIs

Article bodies are stored as HTML partials in `/content/` and referenced by a tile's `content_file` field.

### `GET /api/admin/content/:file`
- **Req**: Path parameter (e.g. `finance_de.html`)
- **Res**: `{"status":"success","content":string,"mtime":int64}` (nonexistent file returns 200 with `content: ""` and `mtime: 0`).

### `POST /api/admin/content/:file`
- **Req**: JSON `{"content": string, "expected_mtime": int64}`
- **Res**: `{"status":"success","message":"File saved successfully.","mtime":int64}`
- **Conflict**: If file was modified on disk since `expected_mtime`, returns HTTP 409 `{"status":"error","message":"...","actual_mtime":int64}`.

### `POST /api/admin/content-suggest-meta`
- **Req**: JSON `{"name": string, "title": string, "content_file": string, "html_teaser": string}`
- **Res**: `{"status":"success","data":{"summary": string, "tags": ["tag1", "tag2"]}}` (LLM-generated).

### `POST /api/admin/content-edit-html`
- **Req**: JSON `{"prompt": string, "html_teaser": string}`
- **Res**: `{"status":"success","html_teaser": string}` (LLM-edited).

### `GET /api/admin/config`
- **Res**: `{"status":"success","config":object}` (frontend `config.json`).

### `POST /api/admin/config`
- **Req**: JSON `{"config_json": string}` (valid JSON string saved to `frontend/config.json`)
- **Res**: `{"status":"success","message":"Configuration saved successfully."}`

## 7. Media & Assets

### `GET /api/admin/images`
- **Res**: `{"status":"success","images":[{"name":string,"url":string,"size":int64,"mtime":int64}],"files":[...]}`

### `POST /api/admin/images/upload`
- **Req**: `multipart/form-data` with field `image` or `file`
- **Res**: `{"status":"success","message":"...","name":string,"image":{"name","url"},"file":{"name","url"}}`
- Images >50 KB are automatically converted to WebP (quality 40, max width 640px).

### `POST /api/admin/images/rename`
- **Req**: JSON `{"old_name": string, "new_name": string}`
- **Res**: `{"status":"success","message":"File renamed."}`

### `DELETE /api/admin/images/:name`
- **Res**: `{"status":"success","message":"File deleted."}`

### `GET /api/admin/assets`
- **Res**: `{"status":"success","files":[{"name":string,"size":int64,"mtime":int64}],"assets":[...]}`

### `POST /api/admin/assets/upload`
- **Req**: `multipart/form-data` with field `file` (stored raw without image conversion)
- **Res**: `{"status":"success","message":"...","name":string,"image":{...},"file":{...}}`

### `POST /api/admin/assets/rename`
- **Req**: JSON `{"old_name": string, "new_name": string}`
- **Res**: `{"status":"success","message":"File renamed."}`

### `DELETE /api/admin/assets/:name`
- **Res**: `{"status":"success","message":"File deleted."}`

## 8. Model Context Protocol (`/api/mcp`)

JSON-RPC 2.0 endpoint for MCP clients. Requires Bearer authentication.

### `GET /api/mcp?action=sse` (or `Accept: text/event-stream`)
- MCP Server-Sent Events stream; emits endpoint URL (`/api/mcp?action=message&sessionId=...`) and keepalives.

### `POST /api/mcp` and `POST /api/mcp?action=message&sessionId=...`
- Protocol version `2024-11-05`, server `leben-mcp` v1.0.0.
- Methods: `initialize`, `tools/list`, `tools/call`.
- Available Tools: `search_tiles`, `get_similar_tiles`, `get_tile`, `translate_tile`, `get_task_status`, `cancel_task`, `save_content_file`.

*Tip: For local development, prefer the standalone TypeScript MCP server in `mcp-server/` (stdio transport, handles RFC 8628 device flow automatically and stores tokens in OS keychain).*
